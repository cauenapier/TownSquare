Key Findings & Issues

❌ Inconsistent Class Naming

Three different naming patterns for essentially the same component type:

  • townsquare__control (controls at top-right)
  • townsquare__action (actions at bottom)
  • townsquare-avatar__profile-button (avatar toolbar)
  • help-button (inline, no consistent class)

❌ Duplicate Style Definitions

townsquare__control (30×30) and townsquare__action (42×42) share ~80% of their CSS:

  • Same border, border-radius, background blur
  • Same hover/focus states
  • Same color transitions
  • Only differs: size, shadow, and font weight

❌ Profile Button Isolated from System (Incidental, Not Intentional)

townsquare-avatar__profile-button has different styles purely because it's defined in avatar.mjs instead of shell.mjs—no design reason for the differences:

  • Missing border (has border: 0)
  • Solid background instead of frosted/transparent style
  • No backdrop blur effect
  • Smaller shadow (var(--bshadow) vs full filter)
  • Different hover (color only, doesn't enhance border/background)

Verdict: This is technical debt from code organization, not intentional design. Should match the other 30×30 controls visually.

❌ Help Button Lacks Semantic Class

Help button is styled inline without a consistent class system, making it hard to:

  • Maintain consistent appearance
  • Apply theme updates across the board
  • Distinguish it from other controls visually

⚠️ Toolbar Button Sizing

In touch mode (@media (pointer: coarse)):

  • Controls scale to 40×40px (good for touch)
  • Profile/action buttons don't scale—inconsistent touch targets
  • Toolbar buttons should all be 42×42px for consistency

Refactoring Recommendation: Simple & Clean

✓ Consolidate into Single System

Goal: Remove all duplication, use semantic naming, keep it simple.

Merge three separate button classes (`.townsquare__control`, `.townsquare__action`, `.townsquare-avatar__profile-button`) into one base class with two size variants. That's it.

Why Profile Button is Different (Code Organization)

.townsquare__control

border: 1px solid var(--hair-2) background: color-mix(...78%) backdrop-filter: blur(8px) box-shadow: 0 4px 12px -10px

.townsquare-avatar__profile-button

border: 0 ← missing! background: var(--surface) ← no blur! box-shadow: var(--bshadow)

These differences are incidental (code location), not intentional (design)

The Refactored CSS (Minimal & Clean)

/* Base: all buttons share these styles */
.townsquare__button {
  display: inline-grid;
  place-items: center;
  margin: 0;
  padding: 0;
  border: 1px solid color-mix(in oklab, var(--hair-2) 76%, transparent);
  border-radius: 8px;
  background: color-mix(in oklab, var(--surface) 78%, transparent);
  color: var(--ink-soft);
  backdrop-filter: blur(8px);
  cursor: pointer;
  box-shadow: 0 4px 12px -10px rgba(42, 41, 38, 0.38);
}

/* All states */
.townsquare__button:hover,
.townsquare__button:focus-visible,
.townsquare__button[aria-expanded="true"] {
  color: var(--ink);
  border-color: var(--hair-2);
  background: var(--surface);
}

.townsquare__button:disabled {
  opacity: 0.42;
  cursor: default;
}

Size Variants

/* Small: 30×30 (expand, help, edit pencil) */
.townsquare__button--sm {
  width: 30px;
  height: 30px;
}

.townsquare__button--sm svg {
  width: 16px;

/* Medium: 42×42 (jump, high-five actions) */
.townsquare__button--md {
  width: 42px;
  height: 42px;
  box-shadow: 0 8px 20px -14px rgba(42, 41, 38, 0.42);

.townsquare__button--md svg {
  width: 19px;
  height: 19px;

/* Touch: scale small buttons up */
@media (pointer: coarse) {
  .townsquare__button--sm {
    width: 40px;
    height: 40px;
  }

  .townsquare__button--sm svg {
    width: 18px;
    height: 18px;
  }
}

Implementation Steps

  1. Update widget.css
    • Create .townsquare__button with all shared styles (border, blur, shadow, hover states)
    • Create .townsquare__button--sm (30×30, touch: 40×40)
    • Create .townsquare__button--md (42×42)
    • Delete old: .townsquare__control, .townsquare__action, .townsquare-avatar__profile-button
  2. Update avatar.mjs — Change pencil button class: townsquare-avatar__profile-button → townsquare__button townsquare__button--sm
  3. Update shell.mjs — Change button classes:
    • Expand button: townsquare__control → townsquare__button townsquare__button--sm
    • Help button: townsquare__control → townsquare__button townsquare__button--sm
    • Jump/High-five buttons: townsquare__action → townsquare__button townsquare__button--md
  4. Test: Desktop, touch, expanded mode, dark/light themes, focus/hover states

What This Fixes

  • Removes duplication: ~50% less CSS (shared base class)
  • Single source of truth: Update hover/focus/color in one place
  • Clear semantics: `.townsquare__button` is obvious; `--sm` and `--md` are self-documenting
  • No over-engineering: Just 3 classes; minimal complexity
  • Maintainable: Future button changes are trivial

Toolbar Organization Recommendation

Current toolbar order (left to right in desktop mode):

Input | Pencil (edit) | Jump | High-Five

This is optimal because:

  • ✓ Input takes up the most space (flex: 1)
  • ✓ Edit button is next to input (editing context)
  • ✓ Action buttons (jump/high-five) on the right (secondary actions)
  • ✓ Matches reading direction (LTR)

Optional: Add Help Button to Toolbar?

Currently the help button (?) is in the top-right controls. Alternatives:

  • Keep it top-right: Good visibility, doesn't clutter toolbar
  • Move to toolbar right: Would make order: Input | Edit | ? | Jump | Hi5 (busier)
  • Recommendation: Keep in top-right for now—cleaner toolbar, help is secondary
