FOUNDATION Color Palette

TownSquare uses a warm, humanistic palette with semantic naming. The system emphasizes accessibility (WCAG AAA contrast) and performs across both light and dark themes.

LAYOUT Zone Architecture

TownSquare's layout is built on three independent vertical zones, each with specific height and z-index:

┌─────────────────────────────────┐ │ CONTROLS (UI) z-index: 2B+1 │ ← expand, help buttons │ │ │ ┌─────────────────────────────┐ │ │ │ STAGE (sky) 180px │ │ ← scene, figures, props │ │ │ │ │ └─────────────────────────────┘ │ │ ──────────────────────────────── ← ground line (1px border) │ GROUND (nameplate) 40px │ ← name tags, presence │ ──────────────────────────────── │ ACTION-ZONE (toolbar) 60px │ ← composer, action buttons └─────────────────────────────────┘

Height Variables

Variable Value Purpose
--ts-zone-stage-height 180px Scene canvas (flex in expanded mode)
--ts-zone-ground-height 40px Nameplate band
--ts-zone-action-height 60px Toolbar area

Coordinate System

Props anchor to the ground plane at --ts-ground-level: 0px. This is the stage's bottom edge—the walkable plane for figures. Positioning uses transform (not top/left) to avoid layout thrashing.

LAYOUT Spacing System

Inset & Gap Tokens

Token Value Usage
--ts-controls-inset 8px (10px expanded) Top-right control panel distance
--ts-controls-gap 6px Gap between control buttons
--ts-toolbar-inset 10px Toolbar horizontal margin
--ts-toolbar-gap 8px Gap between toolbar items

Touch Mode

On touch devices (@media (pointer: coarse)), control buttons enlarge from 30×30px to 40×40px, and tap zones expand to 20-34px. Status row adjustments prevent overlap.

COMPONENTS Forms & Inputs

Text Inputs

  • Height: 30px (composer 38px for padding)
  • Font: 17px / 460 weight for comfort while typing
  • Border: 1px --hair in default, --hair-2 on focus
  • Padding: 8px horizontal, 0px vertical (center via line-height)
  • Placeholder: --ink-faint color

Toggle Switch

  • Dimensions: 36×30px (pill-shaped)
  • Track: --surface background with 1px --hair-2 border
  • Thumb: 14px circle, --ink-soft by default, --you-deep when checked
  • Animation: 150ms ease transition (respects prefers-reduced-motion)

Color Swatches

  • Palette swatches: 20×20px circles
  • Inline current-color control: 24×24px circle in the active name editor
  • Border: 2px --surface when active, transparent by default
  • Focus: 2px --you outline
  • Grid: 4 columns, 6px gap

COMPONENTS Identity Tags

The self identity tag stays compact in its resting state. Editing is progressive: the pencil appears beside the tag, then the tag itself becomes the editor after activation.

Resting State

you Pencil appears outside the tag on hover/focus; touch keeps it reachable.
  • The pencil does not reserve layout space inside the resting tag.
  • A transparent hover bridge keeps hover active between the tag and pencil.
  • The pencil uses .townsquare__button --sm; only the glyph is reduced.
  • On coarse pointers, the pencil is visible/reachable instead of hover-only.

Editing State

The tag converts in place into the input and color control.
  • Clicking the pencil opens an inline input inside the name tag, not a modal.
  • The small identity dot becomes a larger clickable color dot.
  • The color palette opens above the tag, anchored to the enlarged dot.
  • Changes save live as the input or color changes; blur/Escape closes the editor.

Source of Truth

Keep implementation details in sync with public/widget/avatar.mjs and public/widget.css. The label collision solver in public/widget/bubble-layout.mjs accounts for the open editor width so the tag remains clamped on narrow screens.

COMPONENTS Dialogs & Modals

Not Used for Rename

The self rename/color flow is an inline identity-tag editor, not a dialog. Use the modal pattern only for overlays such as help, message board, and connections.

Modal Pattern

  • Backdrop: Fixed, inset 0, 34–38% dark overlay with 6px blur
  • Panel: Centered via flex, max 88% width / 86% height
  • Max-width: 320px for help panel, connections (280px)
  • Padding: 14-16px
  • Border: 1px --hair-2
  • Shadow: --tray-shadow
  • Close: Typically an X button or Escape key

Modal Types

Type Max Width Border Accent Content
Help Panel 320px None Instructions, links, about
Message Board 320px 3px --you top border Owner message + unread badge
Connections 280px None Neighbor town links

INTERACTION Motion & Animation

Animation Timing Strategy

Duration Use Case Easing
80–120ms Micro-interactions (button hover, signpost fade) ease
140–220ms State changes (bubbles, overlays, toggles, inline color dot) ease
560–760ms Celebratory actions (jump, high-five) cubic-bezier spring
0.8–3s Walk cycles, bird animations linear
60s Ambient (cloud drift in expanded mode) linear infinite

Core Animations

  • Walk cycle (800ms): Natural gait with counter-rotating limbs, phase-offset legs, vertical bob
  • Jump (560ms): Snappy prep, exaggerated apex at 45%, springy landing
  • High-five (760ms): Synchronized pair gesture, meeting point at 46–58%
  • Typing indicator (900ms): Sequential 3-dot bobbing
  • Cloud drift (60s): Only in expanded mode; paused in reduced-motion

Accessibility: Reduced Motion

All animations respect @media (prefers-reduced-motion: reduce):

  • Animations pause rather than remove (elements stay in place)
  • Transitions snap instantly
  • No flashing or strobing
  • 5 locations in code: toggle switch, clouds, typing, toggle tracks, general keyframes

  • Jumping: Jump animation triggered by action
  • High-fiving: Pair gesture animation (synchronized)
  • Typing: Typing indicator shows above avatar
  • Raised hand: 🙌 emoji appears above avatar

STANDARDS Accessibility

ARIA & Semantics

  • aria-label on all icon buttons (expand, help, edit, jump, high-five)
  • aria-expanded on toggles and profile editor
  • aria-pressed on expand button (reflects expanded state)
  • aria-pressed on color swatches to identify the selected color
  • aria-hidden="true" on decorative SVGs
  • role="img" on semantic emojis (crown, hand)
  • Semantic HTML: <button>, <input>, <section>, <dialog>

Focus Management

  • Clear :focus-visible outlines (2px widget, 3px public pages)
  • 2–3px outline-offset for breathing room
  • Focus restored after modal closes
  • Inline profile editor selects the current name on open and closes on blur/Escape
  • Tab order follows DOM structure
  • Escape key closes dialogs

Contrast & Color

Touch Targets

  • Minimum 30px buttons (40px on touch devices)
  • Name-tag edit pencil is visible/reachable on coarse pointers because hover is unavailable
  • Avatar tap zones: 34–58px via pseudo-element ::before
  • 8px+ spacing between interactive elements
  • @media (pointer: coarse) auto-enlarges controls

Keyboard Navigation

  • Tab: Navigate controls in reading order
  • Enter: Activate buttons, submit forms
  • Space: Toggle switches, press buttons
  • Escape: Close dialogs, clear selections
  • Arrow keys: Move avatars (movement.mjs)

Motion

  • @media (prefers-reduced-motion: reduce) respected everywhere
  • No flashing or strobing
  • Animations freeze rather than remove
  • Subtle, non-jarring transitions (120–280ms)

Mobile & Virtual Keyboard

  • Toolbar mode hides floating UI under virtual keyboard
  • --ts-keyboard variable tracks keyboard height
  • touch-action: pan-y pinch-zoom preserves vertical scroll
  • 100dvh (dynamic viewport height) accounts for mobile bottom bars

STANDARDS Best Practices

Design Principles

  • Semantic HTML first, ARIA second: Avoid over-annotation; use native elements
  • Mobile first: Design for touch targets, then enhance
  • Performance: Use transform for animations, not top/left
  • Warmth: Terracotta accents, brown shadows, cream surfaces (never clinical gray)
  • Accessibility by default: High contrast, clear focus, motion support built in

When Extending the System

✓ DO

  • Use existing tokens for colors/sizing
  • Respect prefers-reduced-motion
  • Test with keyboard + screen readers
  • Add aria-label to icon buttons
  • Scope styles to #townsquare-root
  • Use transform for animations

✗ DON'T

  • Inline color hex values
  • Skip focus indicators
  • Add decorative HTML elements
  • Use auto-playing audio/video
  • Load blocking web fonts
  • Animate top/left (use transform)

Pre-Ship Accessibility Checklist

  • All buttons have aria-label or visible text
  • Focus visible on all interactive elements
  • Modals trap focus and have close buttons
  • Contrast ratio ≥ 4.5:1 (AA) for text
  • Touch targets ≥ 40×40px on mobile
  • Test with keyboard only (no mouse)
  • Test in a screen reader (NVDA, JAWS, VoiceOver)
  • Verify prefers-reduced-motion: reduce works
  • Test in light & dark themes
